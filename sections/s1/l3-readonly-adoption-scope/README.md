# Lecture 3: ReadOnlyから始める安全境界

この演習では、AIをAWS運用の「調査・整理・報告補助」として導入する前に、AIが実行してよい作業、AIは実行しない作業、人間の確認が必要な作業を1枚のスコープ表にまとめます。

## 到達目標

- 観測済みの事実と未検証の仮説を分ける
- ReadOnlyでも扱ってよい情報と扱わない情報を決める
- 作業を「AIが実行してよい（`ALLOW`）」「AIは実行しない（`PROHIBIT`）」「人間の確認が必要（`HUMAN_REVIEW`）」の3種類に分類する
- AIが作業を中断して人間に確認する条件と、確認を依頼するときに伝える情報を明文化する

## 前提条件

- Python 3.10以上
- Markdownを編集できるテキストエディタ
- ターミナル（PowerShell、コマンドプロンプト、または一般的なUnix shell）

AWSアカウント、AWS認証情報、MCP Server、追加のPythonパッケージは不要です。

> **費用と安全性:** この演習はローカルだけで完結し、AWSへ接続しません。AWSリソースを作成・変更・削除しないため、AWS利用料金は発生しません。認証情報をファイルへ記入しないでください。

## セットアップ

1. このREADMEがあるディレクトリをターミナルで開きます。
2. Pythonのバージョンを確認します。

   ```console
   python --version
   ```

3. [`templates/adoption-scope.md`](templates/adoption-scope.md) を作業用の別名でコピーします。元のテンプレートは残しておきます。

## 演習手順

1. [`exercises/scenarios.md`](exercises/scenarios.md) の各シナリオを読みます。
2. 作業用スコープ表の「目的」と「対象環境」を具体化します。アカウントID、実名、実際のログや認証情報は書きません。
3. 各シナリオについて、観測済みの内容を「事実」、追加確認が必要な推測を「仮説」へ分けます。
4. 各作業を次のいずれかへ分類します。

   - AIが実行してよい（`ALLOW`）: 承認済みの情報源を読み、整理し、根拠を示して報告案を作る
   - AIは実行しない（`PROHIBIT`）: リソース、権限、設定、データを変更・作成・削除する
   - 人間の確認が必要（`HUMAN_REVIEW`）: 本番影響、機密情報、費用、例外対応、復旧判断など、人間の責任で判断する

5. ReadOnly境界に、許可する情報源、禁止する操作、出力時の制約を記入します。
6. AIが作業を中断して人間に確認する条件と、確認を依頼するときに伝える情報を記入します。
7. [`examples/completed-adoption-scope.md`](examples/completed-adoption-scope.md) と比較し、曖昧な「必要に応じて」ではなく、誰が見ても同じ分類になる条件へ直します。

## 期待結果

完成したスコープ表には、事実と仮説が分離され、3つの判断区分がすべて含まれます。ReadOnlyの許可範囲、変更操作の禁止、AIが作業を中断して人間に確認する条件が明示されます。

## 検証

完成例を検証します。

```console
python scripts/validate_scope.py examples/completed-adoption-scope.md
```

成功時の出力は [`expected-results/validation.txt`](expected-results/validation.txt) と一致します。自分のファイルを検証する場合は、最後の引数をそのファイルへのパスへ置き換えてください。検証スクリプトは指定したファイルを読み取るだけで、変更しません。

テストも実行できます。

```console
python -m unittest discover -s tests -v
```

## クリーンアップ

AWS側のクリーンアップは不要です。演習で作った作業用Markdownだけがローカルに残ります。不要になった場合も、自分で作成したコピーであることを確認してから通常のファイル操作で整理してください。

## トラブルシューティング

- `python` が見つからない: Python 3.10以上をインストールし、PATHへ追加します。環境によっては `py -3` または `python3` で同じスクリプトを実行できます。
- `INVALID` になる: 出力された不足見出し、判断区分、未解決プレースホルダーを順に修正します。
- 文字化けする: MarkdownファイルをUTF-8で保存します。
- 完成例と同じなのに失敗する: 実行位置がこのREADMEのあるディレクトリか、指定した相対パスが正しいかを確認します。
